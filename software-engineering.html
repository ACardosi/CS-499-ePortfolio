Artifact Description

The artifact selected for this enhancement is InventoryTracker, an Android application originally developed during my Mobile Architecture and Programming coursework in 2026.

The application allows users to create accounts, log in, and manage inventory records by adding, viewing, editing, and deleting items. It was developed using Java, Android XML layouts, and SQLite for local data storage.

Enhancement Overview

The purpose of this enhancement was to improve the application's architecture, readability, maintainability, and separation of concerns without changing its core functionality.

InventoryItem Model

I introduced an InventoryItem model class to represent an inventory record as a single object containing its identifier, name, quantity, and description.

Previously, these values were handled separately, making the code more difficult to maintain. Using a model class improved organization and consistency.

InventoryRepository

I introduced an InventoryRepository class to separate database access from the user interface. The repository retrieves database records, converts them into InventoryItem objects, and returns them to InventoryActivity.

Separation of Concerns

InventoryActivity previously worked directly with database Cursor objects. After refactoring, the activity could focus on displaying information and responding to user actions.

Skills Demonstrated

  • Software architecture and refactoring
  • Model and repository design
  • Separation of concerns
  • Code readability and maintainability

Course Outcome Alignment

This enhancement demonstrates my ability to apply computing techniques and software engineering practices to deliver a maintainable application.

It also demonstrates evaluating design trade-offs. Introducing additional classes increased the application's structure but made responsibilities clearer and future modifications easier.

Reflection

This enhancement taught me that working software can still benefit from improvements to its internal design.

Refactoring InventoryActivity required careful changes to avoid breaking existing inventory functionality. I gained experience with abstraction, modularity, and testing application behavior after structural changes.
