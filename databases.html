Artifact Description

InventoryTracker is an Android application developed using Java and SQLite. It allows users to manage inventory records through account authentication, CRUD operations, searching, sorting, and low-stock identification.

I selected this artifact because its database implementation provided an opportunity to improve reliability, efficiency, security, and maintainability.

Enhancement Overview

Database Constraints

I added database-level constraints to require nonblank item names and prevent negative inventory quantities. This provides an additional layer of data validation.

Parameterized SQL Queries

I improved inventory searching by using parameterized SQLite queries rather than retrieving every record and filtering the complete collection in Java.

Parameterized queries also help protect database operations from unsafe SQL string construction.

Low-Stock Queries

The database can retrieve records whose quantities fall at or below a specified threshold. This reduces unnecessary application-side processing.

Database Indexing

I added an index to the inventory item-name column to support more efficient data access as the inventory grows.

Schema Migration

I updated the database version and added migration logic to preserve existing inventory records when moving to the enhanced schema.

This improves on the previous approach of dropping and recreating tables during upgrades.

Record Timestamps

Inventory records now include a creation timestamp, providing additional metadata that may support future functionality.

Repository Improvements

InventoryRepository provides methods for retrieving, searching, and deleting inventory records. Centralizing database access helps reduce duplicated logic.

Password Protection

The enhanced application replaces plaintext password storage with salted password hashes. This reduces exposure of the original password if the database is inspected.

A production application should use a dedicated password-hashing algorithm such as PBKDF2, bcrypt, scrypt, or Argon2 rather than relying on a simple SHA-256 construction.

Course Outcome Alignment

This enhancement demonstrates my ability to apply well-founded computing tools and techniques to improve an existing application.

It also demonstrates a security mindset through parameterized queries, database-level validation, and improved password storage.

Separating database operations into the repository layer supports maintainability and responsible software architecture.

Reflection

This enhancement helped me understand that database development involves more than storing and retrieving data. A database should also support data integrity, efficient queries, security, and future schema changes.

Schema migration was an important challenge because existing records needed to remain available after introducing new constraints.

Improving password storage also reinforced the importance of evaluating security limitations and understanding the trade-offs involved in technical decisions.
